# GitOps & Version Control Convention Skill

## 1. Conventional Commits Standard
- **Format:** `<type>(<scope>): <short description>`
- **Types:**
  - `feat`: New feature or component creation (e.g. `feat(apex): add student registration controller`)
  - `fix`: Bug fix or self-correction resolution (e.g. `fix(lwc): resolve input validation error`)
  - `docs`: Documentation updates (e.g. `docs(release): add release notes`)
- **Length:** Single line, maximum 72 characters, lowercase without markdown backticks.

## 2. Feature Branch Strategy
- **Format:** `feature/<jira-key>-<short-description>` (e.g. `feature/SCRUM-1-student-app`).

## 3. GitHub Pull Request Documentation Template
Summaries generated by the GitOps agent should follow this structure:
```markdown
## Overview
Brief explanation of the technical changes delivered.

## Key Modifications
- **Apex Classes:** Modified or created controllers
- **LWC Bundles:** UI component changes
- **Metadata:** XML configuration files

## Risk Assessment & Testing
- **Risk Level:** Low / Medium / High
- **Verification:** Unit test execution and security scan results
```
